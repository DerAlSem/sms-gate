# GM+: коды входа через верификацию шлюза

## Зачем

Сейчас GM+ отправляет код входа обычным текстом через `POST /sms/send`. Так код не доходит до абонентов МегаФона, и так его нельзя отправить в Telegram.

Переходите на верификацию. Код придёт сообщением в Telegram от **«Сервисного аккаунта GM+»**. Если Telegram у человека нет или сообщение не дошло, шлюз сам отправит тот же код ниже: по SMS или, абоненту МегаФона, через Telegram Gateway.

Токен тот же. Остальное API не меняется.

## Поток

```
POST /verifications              → id и список маршрутов
POST /verifications/{id}/route   → выбрали маршрут, шлюз доставляет код
POST /verifications/{id}/check   → человек ввёл код
GET  /verifications/{id}         → статус
```

Код генерирует шлюз. Свой код не передавайте.

## 1. Создать

```http
POST /verifications
Authorization: Bearer <token>

{ "phone": "+79991234567" }
```

```json
{
  "id": 9,
  "status": "pending",
  "routes": [
    { "route": "tg_user", "instruction": "Open Telegram…", "number": null },
    { "route": "sms_out", "instruction": "Wait for an SMS…", "number": null }
  ]
}
```

## 2. Выбрать маршрут

**Если в `routes` есть `tg_user`, выбирайте его.** Если нет — первый маршрут из списка.

```http
POST /verifications/9/route

{ "route": "tg_user" }
```

```json
{ "id": 9, "route": "sms_out", "status": "pending", "reason": null, "code": null }
```

В ответе `route` — маршрут, который **на самом деле** доставил код. Он может отличаться от выбранного: у человека нет Telegram, и код ушёл по SMS. Подсказку показывайте по `route` из ответа, а не по тому, что вы выбрали.

## 3. Что показать человеку

| `route` в ответе | Подсказка |
|---|---|
| `tg_user` | «Код отправлен в Telegram от „Сервисный аккаунт GM+“» |
| `sms_out` | «Код отправлен по SMS» |
| `tg_gateway` | «Код отправлен в Telegram» |
| `flash_call` | «Вам позвонят. Не отвечайте: код — последние 4 цифры номера» |
| другое | покажите `instruction` как есть |

Человек может получить код дважды — в Telegram и по SMS, если Telegram ответил с задержкой. Код один и тот же, подходит любой из двух.

## 4. Проверить код

```http
POST /verifications/9/check

{ "code": "4821" }
```

```json
{ "id": 9, "status": "confirmed", "outcome": "confirmed" }
```

`outcome`: `confirmed`, `wrong_code`, `no_attempts_left`, `expired`, `already_confirmed`.

## 5. Статус

`GET /verifications/{id}` — `status`: `pending`, `confirmed`, `failed`, `expired`. Опрашивать нужно, только если хотите узнать, что код не доставлен (`failed`), не дожидаясь, пока человек нажмёт «не пришло».

## Не пришло

Верификация после `failed` или `expired` не возобновляется — создайте новую. Если человек нажал «не пришло», пока статус `pending`, тоже создайте новую.

## Ограничения

- Срок жизни — 5 минут (`expires_at`).
- 5 попыток ввода кода.
- У сервисного аккаунта есть лимит сообщений в час и в сутки. Когда он исчерпан, шлюз сам отправляет код по SMS — вам ничего делать не нужно.

## Ошибки

Везде `422` с `detail.error`, кроме `404` на чужой или несуществующий `id`.

| Где | `error` | Что делать |
|---|---|---|
| создание | `no_route_available` | сейчас доставить нельзя — сообщите человеку |
| создание | `number_blacklisted` | на этот номер код не отправить — попросите другой |
| создание | `no_template` | у нас не заведён шаблон GM+ — напишите нам |
| выбор | `route_not_offered` | маршрут больше недоступен — создайте новую верификацию |
| выбор | `already_selected` | маршрут уже выбран — опрашивайте статус |
| выбор | `refused` | код не отправлен — создайте новую верификацию позже |
| выбор | `verification_failed` / `verification_expired` | создайте новую |

Неизвестные поля в ответах игнорируйте: мы можем их добавлять.
