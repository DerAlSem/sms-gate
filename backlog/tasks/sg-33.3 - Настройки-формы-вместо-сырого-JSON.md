## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Бэкенд: verification_route_order — тип Spec 'str' → 'rungs'; validate_raw отказывает неизвестной ступени (не из routes.ALL_ROUTES) и повтору; пустые части между запятыми пропускает, как delays. Тест.
2. Роутер: в контекст settings.html — список ступеней с человеческими именами (N_ в settings_layout) и REFUSE; messenger_brands/limits отдаются отформатированными (indent=2) — только сохранённое значение, отказ показывает ввод как есть.
3. settings.html: для operator_routes, verification_route_order, send_retry_backoff, inbound_dispatch — форма поверх textarea с тем же name (textarea скрыта, форма пишет в неё на каждое изменение и на submit, шлёт input-событие для метки «не сохранено»). Кнопка «Править как JSON» переключает на textarea; обратно — разбор, при ошибке остаёмся в JSON с сообщением. Отказ сохранения с неразбираемым вводом открывается в режиме JSON.
4. operator_routes: строка на оператора (имя, ступени ↑↓ ×, добавить ступень из неиспользованных, переключатель «Отказать» = ["refuse"]); строки * («любой другой») и ? («не определён») закреплены в конце, без удаления и без поля имени; добавление/удаление прочих строк. Отсутствующая * или ? показывается как «Отказать» — по rule.route_for это то же поведение.
5. inbound_dispatch: таблица (префикс, URL, bearer password); у сохранённой строки bearer пуст с подсказкой «задан (пусто = оставить)», сериализуется сентинелом BEARER_SENTINEL — дальше прежний _resolve_bearer_sentinel.
6. messenger_brands/limits: отформатированный JSON + кнопка «Вставить пример» (при непустом поле — confirm).
7. Русские строки через messages.po (docs/i18n.md). Проверка: pytest, рендер qlmanage, jsdom — серилизация без правок совпадает с сохранённым (JSON-равенство).
