## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
SG-34 (выкачено 26.09, 44ce3b5) сделал запись `verification_templates` парой (app_id, route): route — sms_out, tg_user или нет (запасная для всех ступеней), подстановка {code_words}. Страница /admin/apps/<id> из SG-33.4 знала один шаблон на приложение: правила первую запись с app_id — сохранение затёрло бы запись ступени, превратив её в запасную; а в списке приложений проверка `id in parse(...)` после смены ключа на кортеж всегда ложна — каждое приложение помечено «код по SMS не уйдёт». Экран настроек шаблоны больше не правит (указатель на страницу), так что записи ступеней иначе как руками в базе не изменить. Решение владельца 26.09: три поля на странице — общий, только SMS, только Телеграм.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 На странице приложения три поля: общий текст (запись без route), только SMS (sms_out), только Телеграм (tg_user); пустое поле — записи нет
- [x] #2 Сохранение меняет только записи этого приложения по своим парам (app_id, route); записи других приложений и порядок остальных сохраняются
- [x] #3 Под SMS и Телеграмом видно, какой текст уйдёт: свой, общий или никакого (ступень не используется)
- [x] #4 Список приложений помечает «нет текста SMS» только когда у sms_out нет ни своей, ни общей записи
- [x] #5 Отказ валидатора (дубль, неизвестная подстановка) показывается у поля, ввод не теряется; тесты на всё это; doc-9 обновлена
- [x] #6 Счётчик SMS считает {code} четырьмя цифрами (код шлюза — 4 знака), а {code_words} — четырьмя словами прописью, так что кириллица даёт 70/67

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. router: шаблоны читаются/пишутся по трём слотам (app_id, None|sms_out|tg_user); сохранение одной формой меняет только эти пары, остальное на месте.
2. Список: has_template = sms_out своя или общая запись.
3. app_detail.html: три поля, строка «уйдёт так» и счётчик по действующему SMS-тексту ({code}=6 цифр, {code_words}=6 слов).
4. Тесты, рендер (dump_html + qlmanage, jsdom для счётчика), doc-9.
