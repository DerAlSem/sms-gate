# uCaller — vendor reference, read by layers 22.09.2026

The external-contract gate wants a reference or a captured sample before a parser and
before any claim about what the vendor does. This is the **reference** half for uCaller,
read in full on 22.09.2026 so that the credential's shape stops being a reading of a
reading. No live sample is captured here — that is task 1.3, and see the finding about
test numbers below, which makes 1.3 free.

Source: `https://ucaller.ru/doc` → redirects (200) to **`https://developer.ucaller.ru/`**.
Static HTML, no JavaScript — the whole text is in the served document, so no rendering
step can lose part of it. Pages read: the basics page, `/limits/`, and the method pages
`initcall`, `initrepeat`, `getinfo`, `getbalance`, `getaccount`, `getservice`,
`checkphone`. `og:updated_time` on the basics page is `2022-04-01T14:41:53+02:00`.

## 1. Authentication — this is the answer 1.1 was waiting for

The vendor accepts **three** schemes, and they carry the same **two** values: a
per-service secret key and a service id.

    # query, GET only
    curl "https://api.ucaller.ru/?key=<Секретный ключ вашего сервиса>&service_id=<Идентификатор сервиса>"

    # JSON body
    curl https://api.ucaller.ru/ -X "POST" -H "Content-Type: application/json" \
      -d '{"key":"<Секретный ключ вашего сервиса>", "service_id":"<Идентификатор сервиса>"}'

    # header
    curl https://api.ucaller.ru/ \
      -H "Authorization: Bearer <Секретный ключ вашего сервиса>.<Идентификатор сервиса>"

Both values come from the cabinet, **separately**: "Узнать Секретный ключ вашего сервиса
можно в личном кабинете, в разделе Мои сервисы."

🔴 **So "a single bearer string carrying both an API key and a service id" was a correct
reading of the header form and the wrong thing to store.** The bearer is *derived* —
`<key>.<service_id>` — and it is one of three ways to send the same pair. The vendor's own
cabinet hands over two values and never the joined string. See the settings decision in
`specs/outbound-routing/spec.md`, requirement "A route's credentials live in `settings`".

Failed authentication is `code: 401`, body
`{"status":false,"error":"Authentication failed. Make sure you are using the correct
authentication scheme. (https://developer.ucaller.ru/)","code":401}` — carried over HTTP
**200**, like every other error.

## 2. Hosts

| host | note |
|---|---|
| `https://api.ucaller.ru/` | recommended |
| `http://api.ucaller.net/` | HTTP only, "если возникнут проблемы с сертификатами" |
| `http://api.usa.ucaller.net/` | HTTP only, for estates where Russian IPs are blocked |
| `85.193.85.19` | the API server's IP address, published |

Methods live under `/v1.0/<method>` and take both GET and POST. POST takes JSON
arguments; the answer is always JSON regardless.

## 3. `initCall` — `[GET][POST] https://api.ucaller.ru/v1.0/initCall`

Parameters: `phone` (number, **required**, E.164 digits), `code` (number|string — "Уникальный
4-х значный код", the digits the incoming call's number will end with; generated by the vendor
if omitted), `client` (string, ≤64, our own label for the person, searchable in their
statistics), `unique` (string, ≤64, a UUID v4 **idempotency key** — "идемпотетность
предотвращает повторное списание средств"; a repeat call with the same key returns the first
result without re-initialising and without charging again), `voice` (bool, voice robot reads
the code aloud, RU/KZ only), `mix` (bool, code both spoken and in the number, RU only,
priced differently).

Answer:

    {"status": true, "ucaller_id": 103000, "phone": "7900***1010", "code": "1000",
     "client": "nickname", "unique_request_id": "f32d7ab0-...", "exists": true}

`phone` comes back **masked** — "мы храним только хеш номера и маску". `code` is always a
string, deliberately: "так мы поддерживаем коды от 0001 до 9999, если 0001 вернуть в формате
number он обрежется до 1". `unique_request_id` and `exists` appear only when `unique` was
passed; `exists: true` means this request had already been initialised.

🔴 **The code is four digits, and that is the vendor's range, not a suggestion: 0001–9999.**
Anything this gateway generates for the `flash_call` rung has to fit in it.

## 4. `getInfo` — `[GET][POST] /v1.0/getInfo`, parameter `uid` (the `ucaller_id`)

    {"status": true, "ucaller_id": 103000, "init_time": 1556617525, "call_status": -1,
     "is_repeated": false, "first_ucaller_id": 102999, "repeatable": false,
     "repeat_times": 2, "repeated_ucaller_ids": [103001, 103002],
     "unique": "f32d7ab0-...", "client": "nickname", "phone": "7900***1010",
     "code": "0010", "country_code": "RU",
     "phone_info": [{"operator": "МТС", "region": "Республика Татарстан", "mnp": "Мегафон"}],
     "cost": 0.3, "balance": 568.12}

`call_status`: `-1` = "информация проверяется (от 1 сек до 1 минуты)", `0` = "дозвониться не
удалось", `1` = "звонок осуществлен". Confirms the reading of 08.09.2026 that the spec's
requirement "A placed call is not a delivered code" is written on.

⚠️ **`balance` is the balance *before* this operation was charged** — "Состояние баланса до
списания этой операции". Read as the current balance it is high by exactly `cost`, which at
the boundary means a floor that fires one verification late. The spec's balance-floor
requirement says `getInfo` "returns `cost` and `balance` on every enquiry", which is true and
now insufficiently precise; 4.13/4.23 own the fix.

⚠️ `cost`'s type column says **`bool`** while the example carries `0.3`. A vendor typo, named
here so that a parser is not written to it.

`is_repeated`, `first_ucaller_id`, `repeatable`, `repeat_times` and `repeated_ucaller_ids` are
all marked **`deprecate`** in the reference — the free-repeat mechanism is documented as on its
way out even though `/limits/` still states the allowance. `phone_info` "может быть пустой",
and it is a **list**, not an object, despite the type column saying `object`.

## 5. `getBalance` — `[GET][POST] /v1.0/getBalance`, no parameters

    {"status": true, "rub_balance": 84.6, "tariff": "uni", "tariff_name": "Единый"}

`rub_balance` is "Остаточный баланс на рублевом счете аккаунта" — the balance **remaining**,
unlike `getInfo`'s. Its documented response carries **no `cost` field**, unlike `checkPhone`,
which documents one — so this is free *by inference from the absence of a cost field*, not by
a statement in the reference. If it holds, uCaller's balance can be polled for nothing, which
is the opposite of Telegram Gateway's (measured 20.09.2026: the balance arrives only with a
billed confirming check). One free call against the funded account settles it.

## 5b. `getService` — a credential can be checked without calling anybody

`/v1.0/getService`, no parameters:

    {"status": true, "service_status": 1692, "name": "ВКонтакте",
     "creation_time": 1556064401, "last_request": 1556707453,
     "owner": "example@ucaller.ru", "use_direction": "ВКонтакте приложение"}

`service_status` is misnamed in the reference: its description is "Идентификатор сервиса",
and the example carries `1692`. So **the service id is numeric** — and the setting below
holds it as a string all the same, because a blank string is how this gateway spells "not
configured" and because a wrong id is refused by the vendor either way.

🟢 **This is the credential's self-test.** It needs no phone number, no `uid` and no money,
and it answers both halves at once: a bad pair gives `401`, a good one names the service.
The obvious use is the settings page — "задано" today says only that a row is not blank.
Not built here; recorded as the cheap way to do it.

## 6. `/limits/` — the vendor's own numbers

| limit | value |
|---|---|
| requests per second per IP | 30; over it → HTTP 429. Every answer carries `X-Rate-Limit-Limit`, `X-Rate-Limit-Remaining`, `X-Rate-Limit-Reset` |
| `initCall` per number per minute | 4, with **at least 15 s** between them |
| `initCall` per number per day | 30 — over it **the number is blocked for 10 hours** |
| `initRepeat` earliest | 60 s after the `initCall` it repeats |
| free repeats | 2 per authorisation, if the first call did not arrive |

These are the numbers already carried as settings in `app/settings_store.py`, and they match.
The rate-limit **headers** are new information: the ceiling can be read from an ordinary
answer rather than inferred from a refusal.

## 7. Error codes (HTTP 200 throughout, `{"status": false, "error": ..., "code": N}`)

`0` IP blocked · `1` malformed request · `2` a required parameter missing or wrong · `3` bad
phone number · `4` the service is switched off in the cabinet · `5` error initialising the
authorisation · `9` this country is forbidden by the cabinet's geography settings · `10` this
id does not exist or is not yours · `11` free repeat expired · `12` free repeat limit spent ·
`13` bad attempt at a free repeat · `18` the 4-per-minute or 30-per-day limit for one number ·
`19` "Подождите 15 секунд" · `20` voice authorisation unavailable for this country · `401`
authentication failed · `405` method not supported · `429` too many requests per second ·
`500` vendor internal error · `1001` account blocked · `1002` **insufficient funds** · `1003`
this IP may not call this service's API · `1004` service archived · `1005` the cabinet requires
the phone number to be verified.

🔴 **`1003` is a rung this estate can break from the cabinet**, and `0`/`1003` together mean
the egress address matters. This gateway's egress is not the address it looks like (memory:
`gateway-egress-is-not-the-address-it-looks-like`) — so if a per-service IP allowlist is ever
switched on in the uCaller cabinet, the address to enter is the measured egress, not the
house's. Same shape as the Telegram Gateway cabinet's allowlist.

## 8. 🟢 Test numbers make task 1.3 free

> "Для тестирования вы можете использовать номера телефонов
> **79000000001** — авторизации на этот номер будут всегда успешными
> **79000000002** — авторизации на этот номер будут всегда ошибками (не возможно дозвонится
> до абонента).
> В личном кабинете все тестовые авторизации **не будут тарифицироваться**, а также будут
> иметь статус ТЕСТ."

So the wire shapes of `initCall` and `getInfo` — both outcomes, `call_status: 1` and
`call_status: 0` — can be captured against the live API for **nothing**, as soon as the
credential is in `settings`. That is task 1.3, and with it 4.17's parser, without spending a
kopeck and without the owner's phone ringing.

What it does **not** answer is 1.2, which is a different question: does a real МегаФон handset
actually ring, and do the last four digits match the `code` we passed. A test number rings
nobody. 1.2 stays the owner's paid call.

⚠️ And what a test capture cannot promise is the *populated* shape of a real one: `phone_info`
"может быть пустой", `cost` on a free authorisation is presumably 0, and a parser written only
against test answers has never seen a charge. Capture both, and say which is which.

## 9. `checkPhone` — noted, not wanted

`/v1.0/checkPhone` returns an operator for a number (`provider`, `company`, `mnc`, `region`,
`city`, `mobile`) at a documented `cost` of 0.04. This gateway already resolves operators
through voxlink (`app/lookup/operator.py`), MNP-aware and per-number, so this is a paid
alternative to something already working. Recorded so that it is a decision rather than a
discovery, and left alone.
